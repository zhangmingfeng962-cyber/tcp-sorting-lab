# Python 网络排序实验

服务端通过 TCP 下发同一份原始列表。客户端分别用冒泡排序、插入排序和选择排序升序排列数据，并上报每一步的列表。服务端统计操作、计时和验证结果，同时提供浏览器可视化。

## 在网页上播放和重播

解压源码，进入含 `server.py` 的目录。两端都需要 Python 3.8 或更新版本，可直接运行。

启动服务端并保持终端打开。

```console
python server.py
```

打开 [本地可视化](http://127.0.0.1:8000)，点击「播放排序动画」。服务端会启动本机客户端，通过真实 TCP 连接重新下发原列表和接收每一步。默认数据用时约 21 秒，结果出现后点击「重新播放」即可再演示一次。

如需从命令行运行客户端，也可以在第二个终端执行以下命令。

```console
python client.py --delay-ms 180
```

Linux 或 Jetson 上通常用 `python3`，Windows 如果配置了 Python Launcher 也可用 `py -3`。省略 `--delay-ms` 可立即发送各步结果。排序结束后可再次运行客户端，开始新一轮。服务端按 Ctrl+C 停止。

## 跨设备联调

让两台设备接入能互相访问的同一局域网。查出服务端电脑的 IPv4 地址，Windows 可用 `ipconfig`。以下用 `192.168.1.10` 举例，运行时替换成实际地址。

```console
python server.py --tcp-host 192.168.1.10
```

在另一台设备解压源码包并进入该目录，再运行以下命令。客户端单独运行时只需要 `client.py` 和 `protocol.py`。

```console
python client.py --host 192.168.1.10 --port 5000 --delay-ms 180
```

在服务端电脑打开可视化页面，页首显示从 TCP 套接字取得的两端地址。若连不上，先核对实际局域网地址、目标端口和两台设备之间的网络连通性。需要更换端口时，同步修改服务端的 `--tcp-port` 和客户端的 `--port`。

## 更换数据与对比算法

```console
python server.py --values=3,2,1
python server.py --values=-4,0,4,-1,0
python server.py "--values="
```

以上是三种独立的启动方式，任选一行。默认列表为 `[42, 17, 61, 23, 17, 55, 8, 34]`。支持零至 64 个整数，每个值在 −9999 至 9999 之间。

| 算法 | 实现 | 比较次数 | 交换次数 | 总步数 |
| --- | --- | ---: | ---: | ---: |
| 冒泡排序 | 相邻交换，每轮将最大值移到右端 | 28 | 16 | 44 |
| 插入排序 | 用相邻交换将新元素移入有序部分 | 21 | 16 | 37 |
| 选择排序 | 找到剩余元素的最小值并交换到左侧 | 28 | 4 | 32 |

表格使用默认列表。总步数等于比较次数加交换次数。服务端计时从发出当前算法的任务到收到完成消息，包含 TCP 传输和启用时的演示延时。比较算法时优先看操作次数。所有算法应得到 `[8, 17, 17, 23, 34, 42, 55, 61]`。

## 消息格式

TCP 每条消息是一个 UTF-8 JSON 对象，以换行符结尾，同一连接依次进行三种排序。下标从 0 开始。

| 消息 | 方向 | 内容 |
| --- | --- | --- |
| `job` | 服务端到客户端 | 算法标识与原始列表 |
| `step` | 客户端到服务端 | 比较或交换、两个元素的下标、操作后的列表 |
| `done` | 客户端到服务端 | 排序后的列表 |
| `result` | 服务端到客户端 | 操作统计、耗时及验证结果 |
| `complete` | 服务端到客户端 | 三种算法的回执全部发出 |
| `error` | 服务端到客户端 | 本轮中断的原因，连接仍可写时发出 |

服务端检查每步列表与操作是否一致，并以 `sorted()` 对照最终结果。浏览器通过本机 HTTP 接口 `/api/state` 读取最新状态。
